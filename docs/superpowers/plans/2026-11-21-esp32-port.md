# ESP32 port (ESP32-S31-Korvo-1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The widgets demo and the audio scope (real microphones) run on the ESP32-S31-Korvo-1 from the same sources as on the STM32, flashable by someone who has never installed ESP-IDF.

**Architecture:** The two demos move from prism-stm32 into PRISM as a small library (`examples/embedded/`, with CMSIS-DSP as a wrap), linked by both board repositories. A new repository, `prism-esp32`, is an ESP-IDF project. It builds PRISM through Meson inside a `prism` component, and provides the board's frame sink, touch panel, microphones, UART stream and port hooks. Users flash prebuilt merged images; building needs only Docker or Podman.

**Tech Stack:** C++26 (no reflection), Meson ≥ 1.5, ESP-IDF master (pinned commit, GCC 15), `espressif/esp32_s31_korvo_1` BSP (no LVGL), `esp_lcd` RGB panel, PPA, `esp_codec_dev`, CMSIS-DSP v1.16.2, doctest, Docker/Podman, GitHub Actions.

**Spec:** `doc/design/esp32-port.md` (PRISM). Background: `doc/design/porting-and-devices.md`, `doc/design/profiling.md`.

## Global Constraints

- Board code never enters PRISM, and ESP-IDF headers never reach PRISM's headers.
- No hand-kept list of PRISM's (or the shared apps') source files in any CMake file. PRISM is built by its own `meson.build`.
- The two apps build from the same sources on desktop host tests, the STM32 and the ESP32.
- No LVGL, and no `esp_lvgl_port` (`BSP_CONFIG_NO_GRAPHIC_LIB=1`).
- Display: render ARGB8888 into one PSRAM frame (800×480). On `present()`, convert to RGB565 with the PPA into the `esp_lcd` RGB panel's frame buffers (two). The CPU conversion is the fallback.
- UART0 runs at **921600** for both the console and the profiler dump. The dump is triggered by the **PLAY** button.
- `sdkconfig.defaults`: PSRAM on, C++ exceptions on, CPU 320 MHz, FreeRTOS tick 1000 Hz.
- PRISM options for this target: `-Dsdl=disabled -Dio=disabled -Dtests=disabled -Dfreertos_port=disabled`, with `profiling` passed through.
- Firmware outputs are merged images written at address 0: `widgets.bin` and `scope.bin`.
- Every board check prints one line per check, ending in `PASS` or `FAIL`, as the QEMU firmwares do. Every error the board prints says what to do next.
- One build or test run per build directory at a time. Builds run on Coder (workspace `prism`); the user flashes the board.
- Work on `main` in every repository. Commit with explicit pathspecs. Never push without the user's OK.

## Review Focus

1. **A board without PSRAM, or with PSRAM disabled in sdkconfig:** the firmware must say so on the console ("no PSRAM found: …") instead of crashing on the frame allocation. Task 5 adds this check.
2. **A panel that shifts or tears under load (PSRAM bandwidth):** the display check must keep a known-good mode reachable, through bounce buffers and a configurable pixel clock (`CONFIG_PRISM_LCD_PCLK_MHZ`). Task 6.
3. **The microphone path when the codec doesn't start:** the scope must fall back to the synthetic source and name it in the title, as the STM32 does when its ADC fails. Task 7.
4. **`prism-trace` reading a port where logs and the dump interleave:** the dump must be found and converted with zero warnings, even with log lines before and after it. Task 8 checks this on the board, and `tests/test_prism_trace.cpp` already covers resync on garbage.
5. **`scripts/flash.sh` with no board, or two boards, plugged in:** it must say which, and not guess. Task 9.
