# Orbit 2: real gravity, random scenes, a following camera — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The gallery's Orbit game becomes a real little game: moons and asteroids that move under
everyone's gravity, about ten hand-made levels plus endless random scenes that are proven
winnable, a camera that zooms out to keep the probe in view, and a persistence slider for trails.

**Architecture:** The physics stays pure functions over plain values (tested headless): a
`World` of bodies (fixed anchors and moving bodies) plus a massless probe, stepped with velocity
Verlet at a fixed time step, so a launch always replays the same way. A pure solver searches
launch velocities with that same simulator; the scene generator keeps only scenes the solver can
win. A pure camera function decides the view from the field and the probe. The tab draws it all on
its canvas, as today.

**Tech Stack:** C++26, doctest; the gallery (examples/widget_gallery).

**Spec:** none written; this plan carries the decisions. User's words (2026-11-18): "random
scenes, more levels, mobile objects"; "for moving object the whole fun is gravity"; "an automatic
zoom out to always see the projectile as long as it is not lost"; "being able to set the
persistence depth". Agreed design: fixed anchors + bodies moving under full mutual gravity,
Verlet, seeded random scenes checked by a solver, ~10 hand-made levels teaching one idea each,
camera zoom-out until the probe is lost, persistence = how many past flights stay drawn (0-20,
fading), short fading trails for moving bodies with the same setting.

## Global Constraints

- Determinism: a fixed time step of 1/240 s; the same level, gravity and launch velocity give the
  same flight every time (bit-identical within one build). Moving bodies stay still until the
  launch and start from the level's initial state at every launch (a retry resets them).
- Gravity: every moving body and the probe feel every body (anchors and moving bodies); anchors
  never move; the probe pulls nothing. Softening as today: distance never below the body's radius.
- Integrator: velocity Verlet (kick-drift-kick) for moving bodies and the probe.
- Collisions: probe inside any body's radius → Crashed; a moving body inside an anchor or
  another moving body → both moving bodies involved are removed (an anchor survives).
- Lost: the probe more than 1.5 × the field's diagonal from the field's centre, or flying for more
  than 30 s → Lost.
- Target: a ring at a fixed point, or carried by a moving body (`target_body`), its centre
  following that body.
- Camera: the view is the smallest rectangle with the canvas's aspect containing the field and the
  probe plus a 60-unit margin, never larger than the lost box; it eases toward that with a time
  constant of 0.25 s; once the probe is lost (or the flight ends) it eases back to the field.
- Persistence: a slider 0-20 = how many past flights stay drawn, older ones fainter (alpha
  falling linearly to 15 % for the oldest); moving bodies' trails keep the last `2 s × (1 +
  persistence / 5)` of their path, fading the same way.
- Random scenes: `seed` (uint64) → the same scene everywhere; a scene is offered only if the
  solver finds a winning launch; difficulty 1-5 sets the count of anchors/moons/asteroids.
- Code: example code under examples/widget_gallery/, pure parts in headers split by role
  (no file over ~250 lines), tests in tests/test_orbit*.cpp; AGENTS.md style (KISS, one level of
  abstraction per function, `simplify:` on cuts). Builds on Coder via
  `/tmp/claude-6516/prism_remote.sh`, one at a time; syntax checks via `bash ~/syntax_checks.sh`;
  explicit pathspecs; never push.

**Files:** split `examples/widget_gallery/orbit.hpp` into `orbit_physics.hpp` (Vec, Body, World,

existing ones kept for now, converted); keep `orbit.hpp` as a small include of both if the tab
needs it. Tests `tests/test_orbit.cpp` (extend; keep the existing behaviours).

**Interfaces:**
```cpp
namespace orbit {
struct Body { Vec pos, vel; double mass = 1, radius = 30; bool anchor = true; };
struct Level {
    Vec start; Vec target; double target_radius = 30;
    std::optional<std::size_t> target_body;   // the ring rides this body
    std::vector<Body> bodies;
};
// A body in a circular orbit around `bodies[around]` at `distance`, starting `phase` turns in,
// counter-clockwise unless `clockwise` (speed for gravity 1).
Body orbiting(const std::vector<Body>& bodies, std::size_t around, double distance, double phase,
              double mass, double radius, bool clockwise = false);
struct World { std::vector<Body> bodies; Probe probe; double time = 0; };
World launch(const Level&, Vec velocity);        // bodies from the level, probe at start
Outcome step(World&, const Level&, double gravity, double dt);
Outcome advance(World&, const Level&, double gravity, double seconds, double& carry, double dt = 1.0 / 240.0);
Vec ring_centre(const World&, const Level&);
}
```

### Task 2: The solver and random scenes (pure)

**Files:** create `examples/widget_gallery/orbit_scene.hpp`; tests `tests/test_orbit_scene.cpp`.

**Interfaces:**
```cpp
namespace orbit {
// A winning launch velocity for `level` at `gravity`, if one is found among a fixed grid of
// directions × speeds (each simulated to its outcome).
std::optional<Vec> solve(const Level&, double gravity = 1.0);
// The same scene for the same seed; difficulty 1-5 sets how many anchors, moons, asteroids.
// Only scenes `solve` can win; after 50 unsolvable tries, the simplest winnable fallback.

}
```
