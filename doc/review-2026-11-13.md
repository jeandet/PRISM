## 1. Where PRISM stands

The 2026-11-12 plan is done, except the items that wait on a decision (section 5):
- the application shell: disabled widgets, menus with shortcuts and submenus, button
  shortcuts, settings (also in the browser), light and dark themes;
- several windows, remembered size, place and splitter sizes;
- drag and drop inside the app, reorderable lists and trees, docking with floating panels;
- Python level with C++ for all of that;
- incremental table sort, undo by diffs.

So an app can now have the *frame* of a real desktop tool. Two things are now behind:
1. the scene pipeline still does whole-tree work for every input event;
2. the widget catalog lacks the everyday pieces of a main window (toolbar, status bar)
   and the richer forms of the data widgets (editable table cells, multi-select trees).

AGENTS.md asks not to let the visible features crowd out the scale work. This plan puts
the scale work first.

## 2. Scale: the scene pipeline

1. **One publish per input event.** Each event is its own task on the logic thread, and
   ends by publishing (`app/model_app.hpp:592-593`, `publish_dirty()`). Mouse motion is
   coalesced by the backend (`src/backends/software_backend.cpp:283-302`); key repeat,
   wheel and clicks are not. Fast typing or wheel scrolling publish many times per frame.
   Fix: publish once per batch of queued events (or once per frame), not per event.

2. **Every publish walks the whole tree, about ten times.** `build_snapshot`
   (`app/widget_tree.hpp:763-863`) counts dirty widgets, refreshes them, materializes
   virtual lists, collects viewport heights twice, builds the whole layout tree, measures,
   arranges, adopts popups, flattens and resolves clips. A one-checkbox change pays for the
   whole tree. Measured 2026-11-02: fine below ~10k live widgets. It multiplies with item 1.
   Fix, later: keep the layout tree between publishes and skip clean subtrees.

3. **Nothing inside a scroll view reuses its draws.** The draw cache needs
   `!clipped_by_ancestor` (`ui/layout.hpp:521`). So every visible row inside a scroll,
   a list or a table is copied and translated on every publish (`ui/layout.hpp:541-548`).
   Most real content sits in a scroll. `bench_widget_scale` puts all its widgets in one,
   so it only measures this slow path. Fix: keep draws in widget coordinates and apply
   the offset and clip when rendering, so a cached entry no longer depends on position.

4. **Cross-thread hazards that fail silently.**
   - `Field<T>::set` has no thread check (`core/field.hpp:21-25`), though the logic
     thread is known (`app/model_app.hpp:34`, `detail_is_logic_thread`). A `set` from a
     worker is a data race nobody sees. Fix: assert in debug builds.
   - `SenderHub::emit` copies every callback under a mutex on each emit
     (`core/connection.hpp:101-108`): each `Field::set` allocates.
   - `Channel::drain_notifications` pops everything queued at once, and the queue is
     unbounded (`core/channel.hpp:33-38, 49`). A burst from a producer freezes input.
     Fix: drain a bounded batch per turn and wake again for the rest.

5. **Every frame repaints the whole window.** `src/backends/sdl_window.cpp:317-330`
   clears and replays every draw list, and text is cached as one texture per string
   (`:429-446`). Fine for forms; costly for a large text document. Damage rectangles and
   a glyph atlas are the usual fix. Later.

6. **Not measured:** rasterize and present cost, layout alone, deep nesting, many windows,
   large text, key-press-to-screen latency, allocations per publish. `perf_lab --headless`
   counts the publish side only (`examples/perf_lab/headless_lab_backend.hpp:5-7`).

## 3. Widgets a port hits first

1. **No toolbar and no status bar.** Nothing in `include/` is either. Almost every Qt main
   window has both. A toolbar needs toggle buttons too (item 3).
2. **No fixed choice over a list known at run time.** `Dropdown` needs a scoped enum
   (`ui/delegate.hpp:333`); `ComboBox` always accepts free text (`:820`). Serial ports,
   recent files, a list from a server: no proper widget.
3. **No toggle button.** `Button` has no checked state (`ui/delegate.hpp:722-731`): no
   toolbar toggles, no segmented control.
4. **No group box or collapsible section.** Forms group only with plain stacks.
5. **`Label` is thin.** No word wrap, no link, no image (`ui/delegate.hpp:65-69`). Dialogs
   work around it with a read-only `TextArea` (`app/view_builder.hpp:184-187`). There is no
   image widget at all.
6. **Table cells are text only.** `TableSource` has `cell_text` and nothing else
   (`ui/table.hpp:30`): no editing in place, no checkbox or icon in a cell, no column
   hide or reorder.
7. **Tree is basic.** Single selection (`ui/tree.hpp:180`), no checkboxes, no rename in
   place.
8. **The list has no selection** (`app/view_builder.hpp:681`: a row-click callback only).
9. **No date, time or color picker.**
10. Smaller: no input masks or validators beyond the field's own; no tri-state checkbox;
    tabs without a close button; SpinBox typing has no caret (`delegates/form_delegates.hpp:341`);
    combo suggestions stop at 8 (`delegates/text_delegates.hpp:677`); submenus always
    open to the right (`delegates/menu_delegates.hpp:77`); shortcut labels say "Ctrl" on
    macOS too (`ui/shortcut.hpp:113`); menus on hidden tabs still answer shortcuts
    (`app/widget_tree.hpp:717`).

## 4. Code health

1. **`widget_tree.hpp` is 1918 lines again.** Seams, each a header of its own:
   - the popup stack (`:199-360`) and popup content (`:1504-1640`);
   - the scrollbar/split drags (`:436-545`) and the drag-and-drop state (`:620-717`);
   - building WidgetNodes from Nodes and wiring them (`:917-1313`);
   - the materializers (`:1642-1912`), the table one first (`:1742-1880`).
   AGENTS.md's description of the split is out of date.
2. **`python/src/prism_ext.cpp` is 3712 lines**, the module body alone 895
   (`:2818-3712`). Split along: thread and dispatch, bound handles, PyModel, plot,
   tree/table, and the module's ViewBuilder / Model / free-function bindings.
   Its `field_set_dispatch` (`:368`) and `field_add_dispatch` (`:480`) repeat
   `list_op_dispatch` (`:1104`); the comment at `:1100` says so.
3. **`model_app()` is 263 lines** (`app/model_app.hpp:348-611`), blocks marked by
   comments: extract them.
4. **Other repeats:** the text field's and the text area's input handling share most of
   their code (`delegates/text_delegates.hpp:287-326`, `:594-652`); the three
   `table()` builders repeat their setup (`app/view_builder.hpp:812, 830, 850`).
5. **Stale design docs.** `doc/design/widgets-and-sentinels.md` calls `Toggleable` and
   `SliderRenderable` implemented; neither exists. It also names `widget.hpp` and text
   helpers that do not exist. `doc/design/input-events.md:33` names `core/keys.hpp`
   (the keys are in `input/input_event.hpp`). `doc/design/threading-model.md:50, 92`
   describe a handshake and a `request_redraw()` that are not in the code.
6. `ui/tree.hpp:177, 354`: `detail_tree` should read `tree_detail`, as elsewhere.

## 5. Waiting on a decision

- **Drags between windows.** Wayland gives no pointer position outside the app's windows,
  so this needs the OS drag and drop; SDL3 takes drops but cannot start a drag.
- **Translations:** gettext-style catalogs, or Fluent (plurals and gender done properly).
- **Printing:** SDL has no print dialog; each platform needs its own.
- **Accessibility bridge** (AccessKit): skipped unless simple; it is not. The access
  tree also has no bounds yet (`app/access_tree.hpp:23`).

## 6. Plan

### P0 — the pipeline (days)

1. **Publish once per batch of events**, not once per event. Measure first and after with
   a test that sends a burst of keys and counts publishes.
2. **Assert logic-thread use of `Field::set`** in debug builds; fix what it finds in the
   examples and Python.
3. **Draws inside scroll views reuse their cache** (section 2.3). Add a scrolled variant
   to `bench_widget_scale` first, to show the gain.
4. **Split `widget_tree.hpp`** along the seams above, before the next features grow it.
   Update AGENTS.md.

### P1 — the main window (1–2 weeks)

5. **Toolbar and status bar**, with **toggle buttons** (`Button` gains a checked state,
   or a `Toggle` widget).
6. **A choice over a run-time list of strings** (a non-editable combo).
7. **Group box and collapsible section.**
8. **Label:** word wrap, links; an **image widget**.

### P2 — data widgets (weeks)

9. **Table:** editable cells, checkbox and icon cells, column hide and reorder.
10. **Tree:** multi-select, checkboxes, rename in place. **List:** selection.
11. **Date, time and color pickers.**

### P3 — when a task touches the area

12. The pipeline's bigger steps: keep the layout tree between publishes (2.2), damage
    rectangles and a glyph atlas (2.5), bounded channel drains (2.4), copy-free emit.
13. `prism_ext.cpp` split, `model_app()` extraction, the shared text input code.
14. Fix the stale design docs (section 4.5) when touching those subsystems; the
    `Toggleable` paragraph can go now.
15. The section 5 items, once decided.
