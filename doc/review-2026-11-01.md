## 1. Where PRISM stands against its goal

The goal is a Qt-scale GUI framework, not a demo.

The core is in good shape:

- The reactive model (`Field`, `State`, `Derived`, `List`, `Shared`, `Channel`, transactions).
- The persistent widget tree, with dirty tracking and per-widget draw-list reuse across snapshots.
- Layout, virtualized table and tree, plot with decimation, tabs, split panes, inspector.
- Frame pacing, snapshot and present statistics, `perf_lab`, golden snapshot tests.
- The Python SDK (free-threaded, wheels in CI) and the WebAssembly build.

Most recommendations of `doc/review-2026-08-28.md` are done. Still open: the `WidgetTree`
raw-pointer index, the rest of the `widget_tree.hpp` split, and the app thread hit-testing
against its own snapshot (now documented as a deliberate choice). All 11 items of `doc/handover-2026-09-02.md` are fixed or mitigated (details in §5).

The gap to Qt is not in the core. It is in the layers Qt spent twenty years on:

1. **Text.** This is the biggest gap. See §2.
2. **The widget catalog.** No menus, dialogs, tooltips, context menus, radio buttons, progress
   bars, or images/icons. There is no image draw command at all.
3. **Platform services.** No clipboard, no drag-and-drop, no file dialogs, no IME composition.
4. **Accessibility.** Nothing. `WidgetNode` carries no role, name or state.
5. **Rendering fidelity.** `RoundedRect` ignores its radius (`src/backends/sdl_window.cpp:383`).
   Circles are aliased.

None of these is an architectural dead end. The seams (snapshot, draw list, `Widget<T>`
dispatch) are the right ones. They are missing subsystems.

## 2. The text problem, step by step

1. There is one font: JetBrains Mono, monospace (`src/meson.build:28`). *(Fixed the same day:
   Noto Sans for UI text, JetBrains Mono for code — see P1 status.)*
2. Widgets do not measure text. They estimate it: `char_width() = 0.6 × font size`
   (`include/prism/ui/delegate.hpp:99`). This only works because the font is monospace.
3. So a proportional font, a second font, or any non-Latin script breaks every label, table
   column, tab width and plot tick at once.
4. Text editing counts bytes, not characters. Backspace erases one byte
   (`include/prism/delegates/text_delegates.hpp:94`, `:295`). Typing "é" then backspace leaves
   half a UTF-8 sequence in the field. This is a live bug.
5. The renderer rasterises every text command into a new texture on every present
   (`src/backends/sdl_window.cpp:309`). There is no cache. It is the dominant per-frame cost for
   text-heavy screens, and worse on the web.
6. IME composition (`SDL_EVENT_TEXT_EDITING`) is not handled. No selection, no clipboard, no undo.

Text decisions leak into every widget. The longer the `0.6 × size` estimate stays, the more code
depends on it. That is why text is first in the plan.

## 3. A threading gap the docs hid

The README promises an idle app uses zero CPU, and tells you to feed the UI from workers with
`Shared<T>::set()` or `Channel<T>::send()`. Both are true separately, but not together:

1. `Shared<T>::set()` and `Channel<T>::send()` only store the value
   (`include/prism/core/shared.hpp:22`, `channel.hpp:18`). They do not wake the logic thread.
2. Their observers run in `drain_shared()`, which only runs when some frame happens: input, an
   animation tick, or a `post()` (`include/prism/app/model_app.hpp:259`).
3. So an idle app fed by a worker shows stale data until the mouse moves.
4. `model_system_monitor` hides this with an animation callback that never ends
   (`examples/model_system_monitor/model_system_monitor.cpp:180`). That keeps it busy every frame.

The Python SDK does not have this problem: its mutations go through `post()`.

**Update (same day): fixed** — P0 #1 below. `Shared`/`Channel` now call a waker bound by
`model_app`.

## 6. Plan

Ordered so the cheap fixes to the core promise come first, then the thing that gets more
expensive every week (text), then breadth.

### P0 — small fixes to the core promise (days)

**Status: all four done on 2026-11-01** — #1 `973077a`, #2 `4379d3e`, #3 `6b07493`, #4 `adc1990`
(the CI lane is unproven until its first GitHub run).

1. **`Shared<T>`/`Channel<T>` wake the logic thread.** Give them an optional wake hook (a plain
   callable, so `core/` stays app-free). `model_app` binds it to the same path as `post()`.
   Test first: a worker `set()` with no input must publish a new snapshot. Then remove the
   perpetual animation from `model_system_monitor` and check it goes idle.
2. **UTF-8-correct text editing.** Caret moves and backspace/delete step by code point.
   Reproducer test first ("é" + backspace).
3. **Route `KeyRelease`.** The backend emits it (`software_backend.cpp:364`); the router has no
   branch for it (`include/prism/app/event_routing.hpp:112-116`).
4. **An explicit Linux reflection CI lane** (GCC 16). Today reflection is only tested because the
   `macos-gcc` lane happens to get Homebrew GCC 16.

0. **Wait-free snapshot handoff — deferred after measurement**: no measurable lock wait in
   `perf_lab`, even with the CPU overloaded. Build it as a backend-neutral component when the
   second backend starts (spec below). Original rationale: Today the app→render
   handoff takes `windows_mutex_` and a lock-based `atomic<shared_ptr>`. If the app thread is
   preempted inside either, the render thread waits. That breaks the frame contract ("the app
   never blocks the renderer"). Replace it with a per-window mailbox: one atomic pointer slot,
   one `exchange` per side. Measure with `perf_lab` before and after. Design:
   `docs/superpowers/specs/2026-11-01-wait-free-snapshot-handoff-design.md`.

5. **Text measurement the logic thread can use.** A small `TextMetrics` interface in `core`/`ui`.
   The SDL backend implements it with SDL3_ttf (`TTF_GetStringSize`). Headless tests keep a
   monospace implementation. Replace every `char_width()` call. Cache by (font, size, string).
   Add ellipsis for text that does not fit.
6. **Text render cache.** Cache the texture per (string, size, colour) in `SdlWindow`, evicting
   entries unused for a few frames. Measure with `perf_lab` before and after. A glyph atlas can
   come later if the cache is not enough.
7. **A proportional UI font, plus font roles** (UI, monospace, bold) in `Theme`. SVG export
   uses the same font instead of hard-coded `monospace` (`render/svg_export.hpp:80`), so
   screenshots keep matching the app.
8. **Text editing completion:** selection, clipboard (`SDL_GetClipboardText`), undo,
   IME composition (`SDL_EVENT_TEXT_EDITING`).

Forcing function for P1 and P2: a **text-heavy reference app**, such as a log viewer or notes
editor with a file tree, an editor pane, a menu bar and dialogs. Dashboards exercise plots; this
exercises text, focus, menus, dialogs and the clipboard, which is where PRISM is thin.

### P2 — catalog breadth (in the order apps need it)

9.  **Accessibility metadata first:** role, name, state on each `Widget<T>`. Cheap with ~15
    widgets, a rewrite with 50, so it goes in before the catalog grows. A bridge (e.g. AccessKit)
    can come later.
10. **Rendering fidelity floor:** `RoundedRect` radius and anti-aliased circles via
    `SDL_RenderGeometry`. Menus and dialogs will look wrong without it.
11. **`Image` draw command and icons.** Needed by menus, toolbars and trees.
12. **Tooltips, menus, context menus, modal dialogs.** First write a short design note: in-window
    overlays or real OS windows? That choice decides whether `WindowRegistry` needs window kinds.
13. **Table interactivity:** header-click sorting, row selection, column resize. Today
    `TableState` holds only sizes (`include/prism/ui/table.hpp:243-258`); the system monitor
    sorts through a dropdown in its model.
14. **Small widgets:** radio group, progress bar, spin box.

### P3 — hygiene and decisions, when a P1/P2 task touches the area

15. Replace the raw-pointer `index_` in `WidgetTree` with id-based lookup.
16. Move virtualization materialization out of `widget_tree.hpp`.
17. Input/render skew: input is hit-tested against the latest *published* snapshot, which can be
    newer than the one on screen (`include/prism/app/window_registry.hpp:15-22`). Pin it with a
    test, or route against the last presented version.
18. Decide the backend story. Recommendation: commit to SDL3 as the platform layer. For Phase 5,
    try **SDL_GPU** (Vulkan/Metal/D3D12 behind one SDL API) before writing a raw Vulkan or
    WebGPU backend. Then delete the "backend `.so` per renderer" plans from the docs.
19. Decide Windows: supported (add a CI lane) or explicitly out of scope for now. Today it is
    neither tested nor documented.

### Not planned now

- **Damage-rect repaint**, unless measurement says otherwise. The renderer is GPU-backed, where
  full repaint is normal (Qt Quick and Flutter do it), and the known cost is text rasterisation,
  which P1 #6 removes. After #6, compare present time against publish time in `perf_lab`
  (desktop and wasm). Revisit only if presents dominate.
- **Tracy integration.** `perf_lab` and the snapshot/present stats cover today's questions.

## 8. Algorithms from the literature

Surveyed by opencode on 2026-11-01. Citations were checked against Crossref/arXiv;
"unverified" means the fetch failed, not that the work is doubtful.

| Area | PRISM today | Candidate | Verdict |
|---|---|---|---|
| Snapshot handoff | `windows_mutex_` + lock-based `atomic<shared_ptr>` | Per-window atomic mailbox (single `exchange` each side: **wait-free**). Hazard pointers — Michael, IEEE TPDS 15(6), 2004, doi:10.1109/TPDS.2004.8 — not needed: one reader per window | **Adopt with the second backend**: measured no lock wait today (P1 #0) |
| Post queue / `Channel` | Vyukov-style MPSC list: push is one `exchange` (wait-free), pop is lock-free | YMC — Yang & Mellor-Crummey, PPoPP 2016, doi:10.1145/2851141.2851168; wCQ — Nikolaev & Ravindran, SPAA 2022, doi:10.1145/3490148.3538572 (wait-free, bounded memory) | Later: a handful of pushes per frame, no contention. Revisit if `perf_lab` shows the queue |
| `SenderHub::emit` | Copy receivers under a mutex, call outside | Copy-on-write array with wait-free readers | Later: emit calls user code, so it can never be wait-free as a whole; the per-emit allocation is the real cost |
| Text rendering | Rasterise + upload every string every frame | Glyph atlas with shelf/skyline packing (engineering). Slug — Lengyel, JCGT 6(2), 2017 (unverified); MSDF — Chlumský, MSc thesis, CTU 2015 (unverified) | Atlas: **adopt** (P1 #6). Slug: no (needs a GPU outline pipeline). MSDF: later, only for zoomable text |
| Plot decimation | Exact per-column min/max | M4 — Jugel et al., PVLDB 7(10), 2014, doi:10.14778/2732951.2732953 (adds first/last per column: continuity). MinMaxLTTB — Van Der Donckt et al., IEEE VIS 2023, doi:10.1109/VIS54172.2023.00013 | M4: later, if `perf_lab` shows column gaps. MinMaxLTTB: no (loses exact extremes) |
| Layout | Full measure + arrange every publish | Cassowary — Badros, Borning, Stuckey, ACM TOCHI 8(4), 2001, doi:10.1145/504704.504705. Incremental attribute evaluation — Reps, Teitelbaum, Demers, TOPLAS 1983 (unverified) | Cassowary: no (a flex tree has no constraints to solve). Per-subtree measure cache: adopt after a 10k-node measurement |
| Derived values | Eager recompute on dependency change | Adapton — Hammer et al., PLDI 2014, doi:10.1145/2594291.2594324 (demand-driven) | Later: only if eager `Derived<T>` recomputation shows up in profiles |

Rule kept from this pass: **wait-free where a thread must never wait on another** (the render
thread on the app thread). Elsewhere, uncontended lock-free or even a mutex is fine until a
measurement says otherwise.
